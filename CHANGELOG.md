# Changelog
All notable changes to this project will be documented in this file.


## [unreleased]

### Breaking

- The Rust ABI now matches the globals/Demesne model (M5.75 chunk 4, closing the milestone): `buck_engine_create/destroy/tick` and the `buck_engine_test_*` probes are **deleted outright**, replaced by `buck_globals_init(config)` / `buck_globals_shutdown()` / `buck_globals_tick(dt)` (the global tick counter and a GLOBAL poison latch whose recovery is re-initialization — the Rust half of the C# wedge-then-Shutdown-then-Initialize flow; shutdown works on poisoned and never-initialized globals alike, and its exit-drain is what delivers the final log tail) and `buck_demesne_create()` / `buck_demesne_destroy(rid)` (the multi-instantiable render-residency unit: near-empty until M6, carrying the RID registry and per-instance poison inherited from the retired engine, with `buck_demesne_test_panic`/`buck_demesne_test_log_then_panic` as the permanent probes; `buck_globals_test_panic` is the global latch's own probe). `FfiCode.EnginePoisoned` is renamed **`Poisoned`** (discriminant 4 unchanged) — it latches per-scope now, not per-engine. C#: the new `Demesne` class (create-through-ctor, idempotent Dispose) carries the handle and the **deliberately dormant** thread-local `Demesne.Current` (Ghi lineage; nothing engine-side reads it until M6's render scoping — the demo usergame pins the pattern by creating one, publishing it, and tearing it down in module Shutdown). `Engine.TickCount` is now assigned from the native counter's return, making C#/Rust tick desync structurally impossible. `EngineConfig` keeps its name (it configures Engine, the globals facade).

- Winit hoisted into the host-desktop module; the wasm stubs are dead (M5.75 chunk 3). The desktop platform layer — the winit/softbuffer event loop, the window registry, and the `buck_platform_*`/`buck_window_*` exports, symbol names unchanged — moved from core to the `buckminster-host-desktop` crate (`src/host-desktop/rust/platform.rs`); core's `window` cargo feature, its winit/softbuffer dependencies, and the entire stub module are deleted, so the wasm archive now contains **no windowing symbols at all** (nm-verified) instead of loud stubs — the wasm executor simply never links the desktop platform crate. Core keeps the platform EVENT VOCABULARY (`PlatformEventRaw`, event/modifier constants, `KeyCode` + its probe exports): the keycode list is now the exported `keycode_list!` callback macro, which core's enum and host-desktop's winit translation BOTH consume, preserving the single-source no-drift property across the crate split. C# side: `ModulePlatformDesktop` moved to the host-desktop assembly (namespace `Buckminster.Host.Desktop`), and `ModuleWindow` now wires through the new internal core seam `IPlatformWindowing` (pump/poll/create/destroy/set-title — exactly what ModuleWindow consumes) via an internal constructor; the public parameterless constructor builds virtual-window compositions, so games and tests never touch host types. The ignored display-server smoke test (`window_live.rs`) moved to the host-desktop crate with it.
- The C# engine lifecycle is restructured around static globals (M5.75 chunk 2; the Rust ABI is untouched — the demesne split is a later chunk). The per-instance `Engine` class, `Engine.Create`/`Dispose`, `RegisterModule`, and the thread-local `Engine.Current` are **gone**. In their place: the static `Engine` facade — `Initialize(config, logSink, modules)` taking a **host-assembled boot list** (the host constructs its platform modules and a pre-wired ModuleWindow; the usergame contributes core-typed modules and never touches host types — `UsergameDemo.Register*` became the `Modules()`/`ModulesWindowed(moduleWindow)` factories), `Shutdown()` running each initialized module's new `IModule.Shutdown()` in reverse recorded init order before native teardown, `QueueExit`/`ExitQueued`, `IsReady`, `TickCount`, and the new app-lifecycle channel (`LifecycleEvent` enum, `Engine.NotifyLifecycle`, the `Engine.Lifecycle` event — consumer-proven by test; **no host produces these yet**). `IModule` methods lost their engine parameter (globals are ambient) and gained mandatory `Shutdown()` — a throwing module Shutdown is reported through the log pipeline and teardown continues (never held hostage), only modules whose Initialize completed are torn down (the recorded-prefix rule, pinned by test), and `ModuleWindow.Shutdown` now destroys any still-live windows (previously an exit outside the cooperative-close path leaked native windows until process exit). Initialize/Shutdown are cyclable in-process — Initialize returns every static (including the Lifecycle invocation list) to virgin, pinned by a two-cycle no-bleed-through test — which is also what lets each test own a full engine cycle. Registration-after-init and registration-from-inside-Initialize are no longer representable (the boot list is fixed at Initialize); duplicate concrete types are rejected at Initialize. `Engine.Current` returns as `Demesne.Current` in the demesne chunk; the log-sink-delivery routing seam it carried moves there with it.
- `MainLoop` (M5.75 chunk 2): the core-provided frame composition — hosts have no interface; each drives `MainLoop.Iterate()` at its platform's cadence and **pacing lives in core**. Iterate converts monotonic elapsed time into 0..N fixed-step ticks (`MainLoop.FixedStep`, default 1/60, reset by Initialize) plus one render, with the accumulator starting at the Ready latch (init time never becomes a tick burst; sim tick 0 stays pinned to Ready), a spiral-of-death clamp (`MaxStepsPerIterate`, excess dropped), and an ExitQueued check between steps so a queued exit ends the burst — the desktop smoke's exact `ticks=100` sentinel is timing-independent because of it. The desktop host's hand-rolled pump/tick/render loop and its fake fixed dt are deleted; heartbeat pacing (the windowed sleep) stays host-side, and the headless smoke now runs ~1.7s of real-time pacing to tick 100. The primitives (`Engine.PumpEvents/Tick/Render`) remain public statics — the granular seam for tests and the future replay harness.

### Added

- Host-as-executor native composition + multi-crate binding generation (M5.75 chunk 1): the shipped native artifact is now built from the *host's* Rust crate, not core — the new `buckminster-host-desktop` crate is the desktop link root (core's rlib linked in; core drops its cdylib crate-type), the wasm hosts have no Rust half so core stays the wasm staticlib root, and every executor artifact carries the one agreed library name **`buckminster`** (`libbuckminster.so` / `buckminster.dll` / `buckminster.a` — renamed from `buckminster_core`, which core's own rlib filename makes unusable: cargo output-filename collision, rust-lang/cargo#6313). Core-without-host is a supported embedding stance (link `buckminster-core` into your own executor, supply your own loop). Binding generation is multi-crate: ffigen routes each exporting crate's dump entries to that crate's own C# assembly via an explicit crate table (own gitignored `Generated/` dir, own namespace and `NativeMethods`/`Native` partials, per-crate `Library` const now emitted rather than hand-written; unknown crates and non-core mirror/trait *definitions* stay loud GenErrors), and native-symbol collisions across crates are refused at generation time. The permanent multi-crate canary `buck_test_host_probe` lives in the host crate and is exercised by the desktop smoke run at startup; the nm-verified evidence pins that rlib-defined `#[no_mangle]` exports survive into the executor cdylib and that the wasm archive carries core's exports but not the host's.
- `#[buck_trait(internal)]` (M5.5 addendum): trait interfaces stay public by default (they are API), but test/infra demonstrators can opt down — the generated interface lands internal in `Buckminster.Ffi`, invisible to game code, reachable by tests via `InternalsVisibleTo`. `ICallbackDemo` is the first user, so games no longer see a test demonstrator in their API surface.
- M5.5 chunk-4 review minors (addendum): release failure in a generated proxy Drop now logs at error with a note on the stashed exception's fate; trait methods named `userdata`/`release` get a friendly macro error instead of a duplicate-field explosion deep in generated code; the unconsumed bool/usize trait-method marshaling paths are fenced until a consumer lands (per the no-unexercised-emission discipline); Engine.Create's cleanup comment records its one narrow leak path honestly; and stale references to the deleted fn-pointer family are purged from the generated NativeMethods header and docs/wasm-toolchain.md.
- C#-implemented Rust traits (M5.5 chunk 4, closing the milestone): `#[buck_trait]` on an FFI-expressible trait generates the `#[repr(C)]` vtable (userdata key + one fn pointer per method + release, `IntPtr` fields C#-side, covered by the generated layout seam), a borrowed Rust impl of the trait for the vtable itself (callback-rule-4-safe invocation without holding locks across the call), and an owning `{Trait}Proxy` whose Drop fires release — the C# thunk unregisters the `CallbackTable` key, so registration lifetime is deterministic, never GC-timed. ffigen generates the **public** `I{Trait}` interface, the canonical `[UnmanagedCallersOnly]` thunks (exceptions stash and return nonzero, never escape), and `{Trait}Thunks.Create`. Trait methods must return `Result<T, FfiError>` (the i32 code is the exception channel — pinned in the deferred entry, enforced by the macro). Converted consumers: **the log sink is now `ILogSink`** — `Engine.Create` registers an adapter over its sink delegate, `buck_log_sink_set` takes the vtable (a recorded ABI change to an internal surface), and Engine's manual key bookkeeping is gone (release handles it, including on sink replacement); **`buck_callback_invoke` and `CallbackFn` are deleted**, replaced by the permanent `CallbackDemo` test trait whose C# implementations pin the value round trip, exception containment via the stash, FFI reentry, and release-on-return on every target. The hand-written FFI surface is now exactly `buck_last_error_message` + `FfiCall`/`CallbackTable`/`CallbackExceptionStash` — the M5.5 done-when.
- Enum parameters in the FFI vocabulary (M5.5 chunk 3.5): `#[buck_export]` fns take `#[buck_enum]` types by value — the enum crosses as its repr scalar with **generated discriminant validation** (an out-of-range value from C# is InvalidArgument naming the enum and value, never a transmuted invalid enum), via the new `BuckEnum` trait every `#[buck_enum]` type now implements (repr type + validated `buck_from_raw`/`buck_raw`). The generated C# is typed at BOTH layers: the raw import and the `Native.*` wrapper take the real C# enum. First consumer: `buck_log` takes `LogLevel` (raw ABI unchanged — the repr is i32), its hand-rolled int-to-level match is gone, and `Log.cs` drops its cast. This also pre-types chunk 4's public log-sink trait interface. One fence relocated: a bare struct param (vs `&T`) is now syntactically indistinguishable from an enum, so it fails on the `BuckEnum` trait bound instead of a prose macro error.
- FFI binding generation, full conversion (M5.5 chunk 3): every expressible export and mirrored type now goes through the generator — logging (`buck_log`), the whole platform surface (pump, bulk event poll, window create/destroy/set-title/size with typed `Rid` handles, the keycode probes), `PlatformEventRaw`, and a new Rust-side `LogLevel` enum as the public C# mirror's source of truth (compile-time-pinned to the log crate's discriminants). The emitter grew its string-in (UTF-8 `fixed` marshaling), `Span<T>` out-buffer, and named-tuple multi-return wrapper emission alongside these first consumers — `Native.PlatformEventsPoll(Span<PlatformEventRaw>)` returns `(uint Written, uint Remaining)`, `Native.WindowCreate(string, uint, uint)` returns the handle — and `usize` returns surface as checked C# `int`. Hand-written `LogLevel.cs`/`PlatformEventRaw.cs` and the platform/logging imports are deleted; **zero "keep in sync" comments remain in the tree**. The hand-written FFI residue is now exactly the fn-pointer family (`buck_callback_invoke`, `buck_log_sink_set/clear` — chunk 4's `#[buck_trait]` food) plus `buck_last_error_message` and the C# callback infrastructure. Two recorded ABI normalizations, both sides regenerated in lockstep: `buck_platform_events_poll`'s capacity is now `usize` (was u32), and `buck_test_keycode_name` no longer reports the needed length on a too-small-buffer error (out-params were always unspecified on error by contract). Exception context strings also normalized to the grep-exact symbol name ("buck_platform_pump failed with ..." where hand call sites had prose like "platform init pump"), and marshaling-rail messages take the generator's uniform shape. ARCHITECTURE's FFI section rewritten around generation (including the pinned error philosophy); PLAN gains the M5.5 milestone section and the deferred entry's as-built annotations.
- FFI binding generation, C# half (M5.5 chunk 2): `tools/lib/ffigen.py` consumes the metadata dump and emits the raw `[LibraryImport]` layer (an additional partial of `NativeMethods`, style-identical to the hand imports it replaces), the idiomatic wrapper layer (`Native.EngineTick(handle, dt)` — PascalCase, values in, return values out, failures as exceptions, Rust `///` docs carried through as XML docs), the mirrored types (`EngineConfig`, `FfiCode`, and the 195-entry `KeyCode`, verified byte-identical in every name and value to the deleted hand mirrors), and a per-struct layout test. Codegen runs on every `./tool.bat build` (SCons `build-codegen`, between the cargo builds and dotnet); output lands in gitignored `Generated/` directories that the emitter owns outright — never checked in, write-if-changed, strays deleted — and a bare `dotnet build` without it fails with the same instructive run-the-tool error as the missing-native-library check. The layout seam is now generator output end to end: `#[buck_struct]` emits a uniform `buck_layout_*` export (buffer of size + per-field offsets, exact slot count demanded so field-count drift is loud) and ffigen emits the matching NUnit test, replacing the hand-written pair — including the "keep in sync" comments, which are structurally impossible to need now. The emitter cross-checks the macro-authored raw signature against its own semantic-role walk and fails loud on any disagreement; vocabulary shapes without a converted consumer yet (strings, slices, ref in-out, multi-value returns) are loud errors pointing at chunk 3 rather than unexercised code paths.
- FFI binding generation, Rust half (M5.5 chunk 1): `#[buck_export]` on an idiomatic Rust fn now generates the `extern "C" buck_*` wrapper — guard rails, null-checked struct/ref pointers, (ptr,len) span and UTF-8 string marshaling, `Result<T>` → out-params, bool-as-u8, and typed `Rid` handles (plain u64 across the boundary, `Rid::from_raw`/`.raw()` glue hidden in the wrapper; recorded as a distinct semantic kind so the emitter can grow typed C# handles later) — plus dump metadata. Export bodies come in two forms, and the split IS the error philosophy (owner call, pinned): `Result<T, FfiError>` is the FFI-problem channel only — stale handles, poisoned engines, wrong-thread calls, protocol violations, surfaced as C# exceptions because hitting one means a bug or a dead object; a fn with no FFI-lifecycle concerns declares plain `fn f(...) -> T`, and domain failures (operations that can legitimately not succeed) are never FfiErrors — they're ordinary returned data. `#[buck_struct]`/`#[buck_enum]` mark mirrored types (an unmarked type in an export signature fails every build via the `BuckMirrored` assertion). The rails stay in `core::ffi` (now a public module — core *is* the base infrastructure, owner call; the macros live in the sibling proc-macro crate `buckminster-ffi-macros` only because proc-macro crates cannot carry runtime code, and their generated code calls back into `::buckminster_core::ffi`). `buckminster-ffi-dump` links core with the dump-only `ffi-dump` feature (excluded from workspace default-members so cargo feature unification can never compile metadata into shipped artifacts) and writes sorted, deterministic JSON — including the macro-authored raw signature, so the chunk-2 C# emitter never re-derives it; the recorded raw metadata is pinned against the actually-generated extern per vocabulary shape by macro-level expansion tests, and every vocabulary rejection is pinned as a loud compile error by a trybuild suite. Pilot conversion: the engine lifecycle exports, `buck_add`, `buck_test_panic`, `EngineConfig`, `FfiCode`, and the 195-entry `KeyCode` all register metadata; every symbol and signature is ABI-identical to the hand-written original (the untouched C# suite is the proof). One behavior improvement rides along: a null `config` to `buck_engine_create` now returns InvalidArgument instead of being undefined behavior.
- Windows CI build check (M5 chunk 4): a `windows-latest` job builds everything — native cdylib, emscripten staticlib, the full solution — through `tool.bat`'s cmd branch, the path a Windows user actually runs (green on its first execution, 2026-07-16). The core csproj now selects the native library by host OS (`buckminster_core.dll` on Windows, `libbuckminster_core.so` on Linux). `tool.bat`'s on-failure `pause` is CI-defused (skipped when `CI` is defined), with the exit code captured explicitly around it as defensive hardening — pause preserves errorlevel today, but an explicit capture survives future edits that wouldn't.
- The desktop host opens a real window (M5 chunk 3): the no-argument path runs the new windowed demo composition (`UsergameDemo.RegisterWindowed`: platform + window modules plus `ModuleDemoWindowed`, which creates a 640x360 window, logs every event it receives, and ends the run on Escape or the close button — destroying its window explicitly before queueing exit, modeling the cooperative-close round trip). `--headless` runs the M4 composition exactly as before and is what the test-all smoke row now passes. The windowed loop carries interim `Thread.Sleep(10)` pacing (honest placeholder until M6 render pacing; the platform pump never blocks). The demo host logs at Info: winit's own Debug/Trace diagnostics flow through the unified pipeline (the log crate is process-global), and the level filter is the knob. Windows are actually VISIBLE thanks to an interim softbuffer clear present on `RedrawRequested` (handled in-callback per winit's pump contract): Wayland maps a window only once a buffer is committed, so the unpainted window was a taskbar entry with no on-screen surface — caught by the owner's live run, the Godot early-window-clear lesson arriving early; M6's WebGPU surface replaces the fill. Verified live on Wayland and X11 (the latter by unsetting `WAYLAND_DISPLAY` — winit 0.29 removed the `WINIT_UNIX_BACKEND` override): window opens `IsViewable`, the center pixel reads back the exact clear color (0x202430), and Resized/FocusChanged reach C# through the full Rust-poll-inject-dispatch path.
- Windowing modules, C# half (M5 chunk 2): `ModuleWindow` (the window abstraction — owns `Window` objects, orchestrates the platform pump, dispatches per-window `Resized`/`CloseRequested`/`Key`/`FocusChanged` events) layered on `ModulePlatformDesktop` (the thin managed face of the Rust winit layer; fail-fast event-loop creation at module init). Windows are platform-backed when a platform module is wired into `ModuleWindow`'s constructor, **virtual otherwise** — virtual windows take events only by injection, which is what makes the plumbing testable headlessly on every cell and is the seam the future recorded-input trace replays through (`Window.Id`, a stable creation-order index, is the identity events name a window by). `ModuleWindow.InjectEvent` is the single event entry; the desktop producer merely calls it. Cooperative close end to end: `CloseRequested` is advisory, `Destroy()` is explicit, and destroying from inside a `CloseRequested` handler is the supported idiom (pinned by test). `KeyCode`/`KeyModifiers`/`KeyEventData`/`WindowEventData` are the plain-data event vocabulary; the C# `KeyCode` mirror is generated from the Rust list and verified exhaustively (every member, both directions, plus counts) against the `buck_test_keycode_name` probe. `PlatformEventRaw` joined the layout-assertion seam — which promptly caught a real parameter-order bug in its own binding on first run.
- Desktop platform layer, Rust half (M5 chunk 1): winit 0.30.13 wrapped in pump mode behind `buck_platform_pump` / `buck_platform_events_poll` (bulk span; events are plain `PlatformEventRaw` records C# pulls — no callback ever fires from the platform layer, keeping callback rule 4 trivially honest against winit's dispatch reentrancy) and `buck_window_create/destroy/set_title/size` (windows are RIDs, allocator tag 2; create queues a command and flushes it through winit's `about_to_wait` — the only place windows can be created — returning a loud error if the loop is dead, never a garbage RID). The layer is a process singleton and thread-bound: the first platform call claims the thread, wrong-thread calls fail loudly (`with_any_thread` on Linux makes "owner" simply whoever called first). Close is cooperative Godot-style: CloseRequested is advisory, only an explicit destroy tears down. On wasm the same symbols export as loud InvalidArgument stubs (winit has no emscripten backend; the export surface stays target-uniform). `KeyCode`: Buckminster's stable raw-key vocabulary (W3C UI Events `code` set, explicit u32 discriminants, macro-generated with the winit mapping so nothing drifts internally; `buck_test_keycode_name`/`_count` exist for the C# mirror's exhaustive sync check). `buck_layout_platform_event` joins the layout-assertion seam. A display-requiring live smoke test ships `#[ignore]`d (`src/core/tests/window_live.rs`, run manually).
- `Engine.QueueExit()` / `Engine.ExitQueued` (M4): the deferred exit seam (GLFW WindowShouldClose lineage). A module mid-Tick sits under the engine's own iteration where synchronous teardown is impossible, so QueueExit sets a flag, the frame finishes, and the host's loop condition is what honors it — the engine itself never acts on the flag (ticking past it is legal and fully functional; pinned by test). Idempotent, legal pre-Ready, throws on a disposed engine; the ExitQueued read stays valid post-Dispose like IsReady/TickCount.
- Demo usergame (M4 done-when): `src/usergame-demo` (`Buckminster.Usergame.Demo`) — the four-part model's usergame, statically linked into the desktop host as the degenerate case of usergame loading. `ModuleDemoClock` + `ModuleDemoReporter` carry a real data dependency through the registry's topo-ordered init; the reporter logs progress through the round-trip log pipeline and queues exit at 100 ticks. The desktop host now registers the usergame and drives pump/tick/render until ExitQueued.
- test-all row `cs-desktop-host`: runs the built desktop host end to end and requires exit 0 PLUS the exact `BUCK-DEMO-EXIT ticks=100` sentinel (exit-0-without-the-demo-running is not a pass); timeout dumps the partial output rather than swallowing it. Both failure paths proven red before trusting the row, per the matrix convention.
- Logging pipeline (M4): Rust `log` crate records buffer in a process-global queue and are delivered to the engine's C# log sink by the **exit-drain at the tail of every FFI call** — records-before-result, unconditionally, so a failed call's diagnostics arrive in order before its exception surfaces, with the causal C# call still on the stack (buffered, never a synchronous callback per statement — callback rule 4: a `log::info!` deep inside borrowed engine state must not re-enter C#). An **emit-time stderr echo** (threshold `EngineConfig.LogStderrLevelMax`, independent of the buffer filter) is the zero-latency, crash-proof channel — and the seam where future network error reporting or an editor-over-socket attaches. **C# logs round-trip through Rust**: the public `Log` facade (`Log.Error/Warn/Info/Debug/Trace`, plus `Log.Ex(exception)` for the full-detail exception dump) calls `buck_log`, so both languages share one buffer, one ordering, one filter, one delivery path — and a C# record is delivered synchronously within its own `Log` call. Calling `Log.*` before any engine exists is a loud error, never silence. `Engine.Create` takes a mandatory `Action<LogLevel, string>` log sink (silent log dropping is banned; discarding is a written-down decision); config re-applies last-wins per create (logging is process-scoped; multi-engine separation is a non-goal). Loss is always loud: overflow drops oldest and the next drain leads with a synthesized Warn report (the one record that is never lost — its count persists until delivered); a throwing sink surfaces its exception from the emitting call, loses only the record it threw on (redelivery would be a poison pill), and the undelivered tail redelivers at the next call's exit; `Dispose` destroys first so destroy's own exit-drain delivers the final tail.
- `RngStream` (M4): seeded PRNG streams — PCG32-setseq, pure 64-bit integer math, verified against the reference implementation's canonical output sequence on every target; the two state words are readable so owners can snapshot/serialize a stream. (The rest of the original determinism-kernel item was deliberately descoped by owner calls recorded in PLAN.md: no general hashing/traversal API ships — serialize/clone/checksum is Dec's when that layer arrives — and the determinism harness is deferred wholesale until a scenegraph/ECS-era sim layer gives it something real to protect. A v0 was built, demonstrated bit-exact hash reproduction across native and both wasm cells, and was then deleted rather than shipped as machinery testing only itself.)
- Multiple engines and the threading model (M4): `Engine.Current` — the thread-local ambient engine (Ghi `Environment.Current` lineage): `PumpEvents`/`Tick`/`Render` scope it to themselves with save-and-restore, so module callbacks and log-sink deliveries see the right engine without handle-threading; hosts may set it directly; unset reads are null. `Render` now throws `ObjectDisposedException` on a disposed engine like its siblings (previously a silent no-op). `CallbackTable` is now locked, closing the last unlocked shared registry — different engines may be driven concurrently from different threads (a single engine's calls remain externally synchronized), with the pinned caveat that the process-global log sink is then invoked concurrently and must be thread-safe. Full model recorded in PLAN.md's foundation decisions.
- C# `Engine` class (M4): `Create(config)` / `Dispose` (idempotent) / `PumpEvents` / `Tick(dt)` / `Render` (no-op until M6) — tick-as-callee, hosts own the loop. Module registry: `IModule` declares dependencies by concrete type; init runs in stable topological order (registration order as tiebreak) inside the first `PumpEvents`, which sets `IsReady`; tick runs in pure registration order. Pre-Ready `Tick` is a harmless no-op (the host idiom is pump-and-tick until Ready). Loud failures: dependency cycles name the cycle path, missing dependencies name both parties, duplicate concrete types and post-init registration are rejected. The desktop host now hosts the real engine.
- Engine lifecycle across the FFI (M4): `buck_engine_create(config)` / `buck_engine_destroy` / `buck_engine_tick` against a Rust `Engine` owned by a registry whose handles are real RIDs (stale and reused-slot handles fail loudly, proven by test). Tick reports the post-tick counter through an out-param — the minimal read-back seam that makes the Rust-side counter testable rather than write-only. Panic policy decided and implemented: a panic caught inside an engine's scope poisons that one engine — every later call on it returns the new `FfiCode.EnginePoisoned` (4) except destroy, which must keep working for teardown ordering; the poison is per-engine, and the containment runs inside the registry lock scope so a panic can never poison the Rust mutex itself. `buck_engine_test_panic` is the permanent probe.
- Layout-assertion seam (M4): `EngineConfig` is the first hand-mirrored `#[repr(C)]` struct, and `buck_layout_engine_config` exports its size and field offsets for the C# test that compares against `Marshal.SizeOf`/`OffsetOf` on every target — the interim protection until FFI binding generation exists.
- docs/wasm-toolchain.md glossary: the incremental-build gap where a new pinvoke signature *shape* regenerates the m2n trampoline table without rerunning the native relink (mono aborts at the first call; fix is deleting the host's `obj/**/wasm/for-*` dirs), hit live at M4 with the first `double` parameter.
- The m2n staleness class now self-heals (`tools/lib/wasmnative.py`): `./tool.bat build` verifies every for-build trampoline-table/binary pair (each table cookie must appear in the linked binary; suffix-match rule accounting for linker string pooling) and force-relinks once on a mismatch; test-all's browser cell does the same for the publish output, which is host-web's only relink point. Zero checkable pairs is a hard error (path drift must not read as green), and staleness surviving a forced relink is a hard error (that's a real bug, not incrementality).
- RID allocator (`src/core/rust/rid.rs`, M4): the generational slotmap behind every future Rust-side object handle — u64 RIDs (32-bit slot index, 8-bit allocator type tag, 24-bit generation; raw 0 reserved as null), `Option` lookups with loud errors on stale/mis-tagged frees, LIFO free list (deterministic reuse order, pinned by test), generation-exhausted slots retired rather than ever aliasing, and a shutdown leak report (dropping an allocator with live entries prints their raw IDs to stderr; richer attribution later). Ported from Godot's `rid_owner.h` with deliberate deviations (per-slot generations instead of the process-global counter; type tag actually in the RID; no lock-free chunking). One shared implementation, instantiated per subsystem.

- Single tool entry point: `./tool.bat <command>` (polyglot sh+batch, runs everywhere), with a self-healing poetry-managed tools venv and a `tools/<command>.py` command registry. Commands: `build`, `test`, `check`.
- Toolchain audit/auto-provisioning (`tools/lib/toolchains.py`): rustup and the .NET SDK are installed user-local when missing (Windows paths untested until the M5 CI build check); C compiler / MSVC Build Tools are audited with install instructions. Pins: `rust-toolchain.toml`, `global.json`, `tools/poetry.lock`.
- SCons build orchestration with pyright strict mode enforced on the build code (`./tool.bat check`); the SCons API is confined behind the typed facade `tools/lib/sconsfacade.py` (checked at basic mode, the quarantine for SCons type suppressions), with the logic-free `SConstruct` shim unchecked.
- Repo skeleton under `src/` organized by module with language subdirs: `src/core` (Rust crate `buckminster-core`), `src/stdcs` (C# assembly `Buckminster`, NUnit tests; dissolved by the M4 restructure — see Breaking), `src/host-desktop` (desktop host executable). ### Breaking

- `IModule` gains `PumpEvents(Engine)` (M5) — every implementor must add the member (an empty body is fine). `Engine.PumpEvents` calls it on Ready-and-later pumps in registration order; the pinned lifecycle contract is that a module's PumpEvents is only ever called after its Initialize completed (the init pump runs no module pumps). Pump/tick separation means events flow while the sim is paused.

- The `Buckminster` assembly is split (M4 restructure for the four-part core/modules/host/usergame model): the engine core is now `Buckminster.Core` (`src/core/cs` — core is one unit spanning both languages) and `RngStream` moved to the new pure-managed utility assembly `Buckminster.General` (`src/general`). Namespaces are unchanged (`Buckminster`, `Buckminster.Ffi`), so consuming code recompiles without edits — only assembly references change. The cross-cutting test suite moved to `src/tests/cs`; `src/stdcs` is gone.

- `EngineStub` and its tests are deleted (M4): the real `Engine` replaces the M0 wiring stub.

- `NativeMethods.buck_callback_invoke` takes the callback as `IntPtr` instead of `delegate* unmanaged<ulong, int, int*, int>` (ABI-identical; call sites cast). Mono's wasm interp-to-native path aborts on function-pointer parameter types in pinvoke signatures, so this is now a standing binding convention: callbacks cross the FFI as `IntPtr`.
